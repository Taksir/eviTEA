# EviTEA release cleanup: work order

This file is a work order for one coding session. It is self-contained. Read it all before you change anything. Taksir decides whether this file stays in the repository after the work is done.

## 1. What this work is for

EviTEA will be frozen soon. Every number in the paper will come from that one frozen version, run once. So any change that alters calls must go in before the freeze. Changes that leave calls the same can come after it.

Your job has two parts.
- Part A: the changes that alter calls, or that non-fly genomes need. These go in before the freeze.
- Part B: the changes that leave calls the same. These can be done in the same session, but each one must keep calls identical.

Section 6 lists what is out of scope. Do not do those.

## 3. Rules

These are firm. If an item seems to need a break of one of them, stop and write it in the report instead.

1. **No other tools' names in code.** No switch, option, module, file, column, function or variable may be named after another TE or SV tool (for example TEMP2, TEforest, INSurVeyor, GenomeDelta, ELITE, TEPEAK). Name each part by what it does: "anchored extension", "family records", "resident-copy test", "fragment size", and so on.
2. **No renames from the release rename list.** That list is kept outside the repository (`paper_draft/RELEASE_RENAMES.md`) and waits for Taksir's go at submission. Leave these names exactly as they are: `--rule-c`, `RULE_C_MAX`, `rule_c_dropped`, `feat_c`, `T_E`, `e_value`, `v2_dropped`, status `DROPPED_V2`, the event-id prefixes `V2FCRC1_EVENT_`, `V2R4_MATE`, `V2R9E_REPEATDIV`, `V3FULLMEM_AP_`, and `--max-rescue-interval-mass`. Avoid other renames too, unless an item below asks for one.
3. **Only Taksir numbers versions.** Do not change `src/evitea/_version.py`, the version in `pyproject.toml`, `CITATION.cff` or `CHANGELOG.md` version lines. Do not create tags.
4. **No person's name in a branch or tag.**
5. **Work on a new dev branch, never on `main`.** Push the branch. You may open a pull request into `dev-merged`. Do not merge it.
6. **No model ids and no AI traces in commits.** No "Co-Authored-By" lines for an AI, no model names, no "generated by" lines, in commit messages, code comments or docs. Commit as `Md Taksir Hasan Majumder <Taksir@users.noreply.github.com>`, like the existing commits.
7. **No default or constant changes unless listed here.** The only call-changing items are A1 to A6. Every other default and constant stays as it is at the base commit. That includes the 250 bp slops, `T_E` 0.0405, the family-identity cutoff 0.98309, the 1 Mb default contig size, the resident-copy enrichment of 2, the depth window, `--identity-min-comparisons` 3 and the relative depth floor default.
8. **Keep hashing light.** Use hashes only to confirm that an archive or a transfer arrived intact. Do not add new hash checks as tests of the code.
9. Each item gets its own commit, with a plain message that says what changed and how it was tested.

### A2. Read length from the sample, not a fixed 125

The library layer assumes 125 bp reads.
- `src/evitea/incumbent/coverage_panel.py:52`: `READ_WINDOW = 125` (exported at `:36`, used at `:123`, `:126`, `:168`, `:266`).

- `src/evitea/languages/internal.py:35`: `READ_LENGTH = 125` (used at `:185`, `:208`). Keep the column name `read_length_block_125` as it is. Only the block size becomes the sample's read length.

What to do: read the length from the sample. Reads are already required to be of one length (the builder refuses mixed lengths, see `tests/unit/test_phase8_msbwt_builder.py:84`). Record the length when the sample is prepared, carry it into the run, and pass it to these modules instead of the constant. Add an option (for example `--read-length`) that overrides it. Write the value used into the run manifest.

Acceptance:
- On a 125 bp sample, the outputs are byte for byte the same as at the base commit.
- With 100 bp and 150 bp synthetic reads, the run completes and the manifest shows the right length.
- A unit test covers the windows at a length other than 125.
- Expected effect on the paper strains: none on the 125 bp strains. MUN-009 (151 bp reads) will run on its full reads.

### A3. Fragment size from the sample, not a fixed 494 and 805

- `src/evitea/incumbent/mate_rescue.py:61`: `FRAGMENT_Q95 = 494.0` (used at `:624`; the docstring at `:20` names 494).

What to do: estimate the fragment-size distribution from the sample's own properly paired reads, and use its 95th percentile. The estimate must be deterministic (same input, same number). Keep 494 as the fallback when too few pairs exist, and say in the log when the fallback is used. Add an option (for example `--fragment-q95`) that overrides the estimate. Write the value used, and how many pairs it came from, into the run manifest. Say in a code comment why the 95th percentile is used: a pair whose span is above it is unlikely to be a normal pair.

**The 99th percentile too (Taksir's decision).** A second fixed fragment number exists: `Q99 = 805` at `src/evitea/constants.py:11`. It is carried in `ScienceProfile.q99` (`src/evitea/constants.py:42`, `src/evitea/config.py:40`) and used in `src/evitea/anchor_pe/anchors.py:43`, `:125-127`, `src/evitea/full_memory/strict_a.py:153`, `:167-169` and `src/evitea/incumbent/complete_routing.py:125-191`. Take it from the same estimate as the 95th percentile, with 805 as the fallback and an override option (for example `--fragment-q99`). Note that `ScienceProfile.__post_init__` (`src/evitea/constants.py:49-71`) refuses any q99 other than 805 under the current architecture id. Take q99 out of that frozen check, and record the value used in the run manifest instead. Do not change the architecture id or the other frozen values in that check. Update the tests that assert 805 (for example in `tests/unit/test_phase1_constants_families.py`) so that they test the default and the override.

Do not change the 250 bp slops (`CANDIDATE_SLOP` at `mate_rescue.py:49`, `junction_groups.py:32`, `split_junction.py:43`; `HOST_SEED_OUTER_PAD` at `mate_rescue.py:65`). They are out of scope.

Acceptance:
- With `--fragment-q95 494` and `--fragment-q99 805`, the outputs are byte for byte the same as at the base commit.
- A unit test with synthetic pairs of known spans returns the expected 95th percentile, and the fallback case is tested.
- Expected effect: calls can change on every sample whose estimates are not 494 and 805. That is intended.
